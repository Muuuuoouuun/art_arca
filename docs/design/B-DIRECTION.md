## 1. 방향과 콘셉트

**한 줄:** "서울의 이번 시즌 공연·전시를 한 장의 소장 목록(레지스트리)처럼 훑고, 라벨로 고르고, 선반에서 꺼내 본다."

- **은유:** 수집가의 캐비닛. 화려한 첫 화면보다 **잘 정리된 목록과 라벨**이 주인공입니다.
- **톤:** 밝은 종이(Paper) 바탕의 차분한 아카이브. 어두운 면은 가이드 같은 "다른 방"에만 씁니다.
- **사용 장면:** 모바일에서 빠르게 번호 목록을 훑다가 → 라벨에서 기간·장소를 확인하고 → 저장하거나 상세로 들어갑니다.
- `DESIGN.md` §1의 "night museum opening crossed with a collector's cabinet"에서 **collector's cabinet 쪽을 주축**으로 삼습니다. 야간 박물관 무드는 첫 화면 연출이 아니라 포인트 요소로만 남깁니다.

## 2. 원칙

1. **목록이 먼저, 이미지가 다음.** 정보(제목·작가·기간·장소)가 이미지 없이도 읽혀야 합니다.
2. **번호는 의미가 있어야 합니다.** 레지스트리 번호는 이번 시즌 목록 안의 순서(기간 시작일 순)이고, 순위·인기를 뜻하지 않습니다.
3. **라벨은 사실만.** 라벨 카드에는 데이터에 있는 값(분야, 기간, 장소)만 씁니다. 가짜 수치(방문자 수, 저장률, 평점 순위)를 만들지 않습니다.
4. **한 화면에 주 행동은 하나.** CTA 문법은 `DESIGN-ROADMAP.md` T6을 따릅니다.
5. **모바일이 기준.** 390px에서 먼저 설계하고 1440으로 넓힙니다. 터치 영역 ≥ 44px.
6. **장식은 문장 부호처럼.** 월계수, 고전 숫자, 이탤릭은 섹션당 한 번 이하.
7. **접근성.** 명도 대비 AA 이상, 키보드 포커스 표시, 모션 감소 설정 존중.

## 4. 정보 구조(IA)와 사이트맵

```
/                         홈 (이번 시즌 레지스트리)
├─ /exhibitions           전시 레지스트리(전체 목록 + 필터)
│   └─ /exhibitions/[id]  전시 상세 (라벨 · 소개 · 방문 정보 · 리뷰)
├─ /guide                 가이드 허브 (장르 5개: 전시·음악·오페라·연극·무용)
│   └─ /guide/[genre]     장르 가이드 (기초 · 용어 · FAQ · 지금 볼 만한 프로그램)
├─ /bookmarks             내 캐비닛(저장함, localStorage)
├─ /about                 소개 (원칙 · 운영 방식)
└─ /mockups/*             디자인 검토용(noindex, 배포 전 제거 또는 환경 플래그)
```

- **주 내비게이션(4):** 레지스트리(전시) · 가이드 · 내 캐비닛 · 소개
- **리뷰는 독립 메뉴가 아닙니다.** 전시 상세 안의 섹션입니다. 리뷰 모아보기(`/reviews`)는 열린 질문(§9)으로 둡니다.
- **전역 요소:** 상단 내비게이션, 시즌 표기(예: `SS 2026`), 푸터(사이트 정보·소개 링크).

## 5. 페이지별 섹션 구조

### 5.1 홈 `/`
| 순서 | 섹션 | 내용 | 데이터 |
|---|---|---|---|
| 1 | 헤더 | 로고, 내비게이션, 시즌 표기 | `site.ts` |
| 2 | 인트로 + 레지스트리 | 한 줄 소개 + 주 CTA "전체 목록 열기" / 오른쪽(모바일은 아래)에 번호 목록 상위 8개: 번호 · 제목 · 작가 · 기간 | `exhibitions` |
| 3 | 선반(On the shelf) | 큐레이션 4개, 이미지 + 라벨 카드(제목 · 분야 · 기간) | 큐레이션 필드 필요(지금은 10건 모두 `featured: true`라 구분 불가) |
| 4 | 가이드 허브 진입 | "처음 보는 장르도 편하게" + 장르 타일 5개 | `guide-data.ts` |
| 5 | 이용 방법 | 훑기 → 라벨 확인 → 저장 → 방문 3~4단계 | 정적 문구 |
| 6 | 푸터 | | |

### 5.2 전시 레지스트리 `/exhibitions`
1. 페이지 머리: 제목, 총 개수(실제 개수), 시즌
2. 필터 바: 분야(category), 기간 상태(예정/진행 중/종료 — `utils.ts`의 `getExhibitionStatus`), 장소
3. 보기 전환: **목록(레지스트리, 기본)** / 선반(이미지 그리드)
4. 목록 행: 번호 · 제목(영/한) · 작가 · 분야 · 기간 · 장소 · 저장 버튼
5. 빈 상태: 필터 결과 없음 안내 + 필터 초기화

### 5.3 전시 상세 `/exhibitions/[id]`
1. 라벨 헤더: 번호, 제목(영/한), 작가, 분야, 기간, 장소, 상태 · 주 CTA(저장 또는 예약 중 하나만 주 행동)
2. 대표 이미지(heroImage), 대표 오브제(iconicObject)는 보조
3. 소개: `description` → `longDescription`, 태그
4. 방문 정보: 기간·장소·운영 정보(데이터에 있는 것만)
5. 리뷰: 평균(리뷰가 있을 때만) · 리뷰 목록 · 작성 폼(localStorage)
6. 같이 볼 전시: 같은 태그/분야 2~4개
7. 이전/다음 전시(레지스트리 번호 기준)

> 현재 상세의 커뮤니티/정보/인사이트 3탭은 구조만 참고합니다. 탭 안의 **가짜 통계 수치는 삭제** 대상입니다.

### 5.4 가이드 허브 `/guide`
1. 머리: 가이드 소개 한 문단
2. 장르 타일 5개(국문명 · 영문명 · 한 줄 요약)
3. 지금 볼 만한 프로그램 묶음(장르별 진행/예정)
4. 처음 관람 팁(공통)

### 5.5 장르 가이드 `/guide/[genre]`
1. 장르 히어로: 제목, 요약, 빠른 사실(QuickFacts)
2. 기초 섹션들(`GuideSection`: 제목·리드·본문·불릿·노트)
3. 용어집(`GuideGlossaryEntry`)
4. FAQ(`GuideFaqEntry`)
5. 지금 볼 만한 프로그램(`GuideProgramItem`, 상태별)
6. 다른 장르로 이동

### 5.6 리뷰 (전시 상세 내부)
- 리뷰 카드: 별점 · 본문 · 작성일 · (닉네임)
- 작성 폼: 별점, 본문, 제출 → localStorage
- 정렬: 최신순만. "인기 리뷰" 순위는 만들지 않습니다.

### 5.7 내 캐비닛 `/bookmarks`, 소개 `/about`
- 캐비닛: 저장한 전시를 레지스트리 행 또는 선반으로 보기, 빈 상태 안내
- 소개: 원칙·운영 방식, 문의 링크(실제 연동이 있을 때만)

## 7. 콘텐츠·데이터 요구

- 이미 있음: `src/lib/data.ts`(전시 10건: 제목·작가·분야·기간·장소·설명·태그·이미지), `src/lib/guide-data.ts`(장르 5개), 리뷰/북마크 localStorage(`site.ts` STORAGE_KEYS).
- 필요함(구조상):
  - 선반 큐레이션 필드(예: `shelfOrder`) — 지금 `featured`는 전부 true라 선반 선정 기준이 없음
  - 레지스트리 번호 규칙: 시즌 내 기간 시작일 순으로 자동 부여(데이터에 저장하지 않음)
  - 시즌 정보(이름, 기간) 데이터화 — ROADMAP T3
  - 전시별 운영 정보(관람 시간, 휴관일, 요금)가 데이터에 없음 → 없으면 섹션 숨김
  - 이미지 없는 전시용 대체 표현 규칙
  - 이미지 대체 텍스트(alt) 작성 기준
- 쓰지 않음: `exhibition-detail.ts`의 임의 통계 수치, AI 생성 순위·추천 점수.

## 9. 열린 디자인 질문

1. 주 서체: 한글 세리프(예: Noto Serif KR)를 헤드라인에 쓸지, 영문 세리프 + 한글 산세리프로 갈지
2. 영문 헤드라인("The registry of a restless city.")을 유지할지, 한국어 우선으로 바꿀지
3. 홈 첫 화면에 이미지를 둘지(지금 B는 목록만) — 둔다면 선반을 첫 화면으로 올릴지
4. 선반 모바일: 2열 그리드 vs 가로 스크롤
5. 모바일 내비게이션: 햄버거 vs 하단 탭 바
6. 어두운 "다른 방" 섹션을 가이드에만 쓸지, 상세 페이지에도 쓸지
7. 리뷰 모아보기(`/reviews`) 페이지가 필요한지
8. 커스텀 커서·필름 그레인·Ambient Sound를 유지할지(기본 끔 제안)
9. 예약(ReservationModal)은 실제 연동이 없는데 유지할지, "외부 예매 링크"로 바꿀지
10. 장식(월계수·고전 숫자)의 허용 위치
